# 实验13A先导：DeepCache原生branch 0–11合法性与前沿扫描

日期：2026-10-01

## 实验设置

- 模型：Stable Diffusion v1.5，FP16，512×512，CFG 7.5。
- 采样器：DPM-Solver++ 2M midpoint，20步。
- 刷新表：balanced8-A，`[0, 2, 5, 7, 10, 13, 16, 19]`。
- 数据：train split第一条prompt，seed 1701；branch 0–11严格使用相同初始latent。
- 每个外部UNet调用先运行同latent完整shadow，再在复用步运行缓存分支；缓存输出推进真实scheduler。
- 部署耗时只累计8个刷新调用和12个缓存调用，不计shadow teacher。
- 本阶段只用于合法性、计时和guided-noise误差筛选，不能代替12类prompt和图像指标结论。

## 完整性结果

- 12个branch全部完成20步闭环，无缺失缓存键、非有限latent或scheduler状态污染。
- 每档均为8次刷新、12次复用，所有刷新步guided-noise误差严格为0。
- 峰值显存为2647.7 MiB，各档基本一致。
- branch坐标与DeepCache原生规则一致：`block_id = branch_id // 3`，`layer_id = branch_id % 3`。

## 结果说明

1. **静态加深不是可行主方案。** 只有branch 0和1仍达到预设的1.50×速度线；branch 1却只比branch 0降低3.9%的复用误差。branch 8–11能恢复约67%–69%的误差，但速度只剩1.006×–1.020×，等价于接近完整UNet。
2. **branch深度不是单调质量旋钮。** branch 7比branch 6更慢，但误差从0.08299恶化到0.09947；branch 9和11也分别被更浅档位支配。这与此前“对称重算有质量作用、但原生局部路径容易产生状态不一致”的证据一致。
3. **阶段调度仍存在明确窗口。** branch 8相对branch 0在step 18把误差从0.2127降到0.0338，增加约2.69秒；step 15和17也分别降低0.1139和0.1124。把深branch限制在一两个敏感复用步，有机会保留超过1.5×的整体速度，而静态branch平均数会掩盖这种机会。
4. **当前证据只有一条轨迹。** 不能据此冻结step 15/17/18，否则会对该prompt过拟合。下一步必须验证敏感step在12个类别上是否稳定。

## 下一步实验

继续实验13A的正式train-only扫描：12类各取1条train prompt，比较`branch 0, 1, 3, 8, 10`。

- branch 0：速度基线。
- branch 1：唯一仍处于1.5×附近的静态档。
- branch 3：中等深度拐点。
- branch 8：出现误差陡降的深档。
- branch 10：深档中最低平均误差，并用于检查branch 8是否已足够。

正式扫描将聚合每个复用step的误差收益和增量耗时，检查晚期敏感step是否跨类别稳定。只有稳定后，才使用train数据构造`depth_fast/mid/quality`固定step表，并做正确step与shuffled-step的闭环图像质量对照。
